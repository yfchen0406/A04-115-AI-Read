3.yfchen網站改版 · 全站搜尋與媒體封存計畫 (詳細版)

一、改版目的與原則

對象：D:\A02-115-yfchen-test 個人網站（累積多年退休生活、閱讀、旅遊、AI 學習、家庭與行政資料）。

四大目標：

  • 改善 VS Code 中 Live Server / Five Server 因大量檔案監看而開啟緩慢的問題。
  • 建立可跨資料夾搜尋的正式入口（全站搜尋）。
  • 減少首頁和共用元件中不必要的圖片、字型與腳本載入。
  • 防止大型原始媒體持續進入 Git，避免專案繼續膨脹。
本次不做的事：不刪除任何文章、原始照片、影片或 PDF；不改寫既有 Git 歷史；不以最佳化圖片覆寫原檔。

完整規劃請參閱 A03-PLAN.md，本報告為執行結果與維護指引。

二、問題評估結果

檔案量與 Git
  • 約 4,729 個 HTML 檔案
  • 大量圖片、影片、PDF 與舊資料
  • Git 歷史約 9.1 GB
  • Pagefind 索引本身含大量小型檔案，需排除監看
Live Server vs Five Server
  • Live Server 讀取 liveServer.settings.ignoreFiles
  • Five Server 使用獨立的 fiveServer.ignore
  • 即使 Live Server 改善，Five Server 仍可能卡住
  • 本次已分別設定排除規則

Pagefind 索引約 1.72 MB，收錄 4,095 個完整網頁（排除 206 個 HTML 片段）。

三、全站搜尋功能（Pagefind）

工具：Pagefind 靜態全文搜尋，無需資料庫或付費 API。官方說明

搜尋頁與入口
  • 正式搜尋頁：S01-Search-1131012.html（保留既有網址）
  • 共用導覽列搜尋圖示已指向此頁
  • 索引語言：繁體中文 (zh-tw)
  • 收錄 4,095 個完整 HTML 網頁（排除約 206 個共用片段）
相關檔案
  • S01-Search-1131012.html – 搜尋介面
  • pagefind.yml – 設定檔（根目錄、輸出、語言）
  • pagefind/ – 自動產生的索引 (須隨網站部署)
  • tools/rebuild-pagefind.ps1 – 一鍵重建索引
  • reports/pagefind-build-history.csv – 每次建立日期與頁數
日後更新搜尋：在網站根目錄執行 ./tools/rebuild-pagefind.ps1，確認歷史紀錄新增一筆，並測試新文章可被找到。

四、媒體封存與最佳化

核心觀念：原始媒體保留於 Git 專案外封存區，網站僅載入較小的 WebP 副本，原始檔永不刪除或覆寫。

封存區
  • 位置：D:\網站原始媒體封存
  • 保留完整相對路徑（例：images/B03-banner/）
  • 首批已封存 4 張首頁原始輪播圖
  • 封存紀錄：reports/media-archive-log.csv
最佳化副本
  • 位置：assets-optimized/images/B03-banner/
  • 產生 480、960、1600 像素 WebP
  • 首頁 4 張圖共 12 個檔案，合計約 0.69 MB
  • 對照表：reports/media-manifest.csv
稽核與工具
  • reports/media-audit.csv – 列出 792 個實際被網頁引用的媒體
  • tools/optimize-web-images.mjs – 掃描引用、建立稽核表、產生 WebP 副本
  • tools/archive-optimized-originals.ps1 – 確認無頁面引用後才封存原始檔
日後新增圖片建議流程：
① 原始照片保存於封存區或暫放網站內 → ② 確認 HTML 引用 → ③ 執行 npm run media:audit → ④ 產生最佳化（npm run media:homepage） → ⑤ 修改 HTML 改用 assets-optimized/ 並加入 srcset、loading="lazy" → ⑥ 確認無頁面引用原圖後，執行封存工具。

大型影片建議使用封面與 preload="metadata"；大型 PDF 改為連結或縮圖開啟。

五、首頁與共用元件載入瘦身

  • 首頁輪播圖使用 srcset、sizes、loading="lazy"、decoding="async"，首張保留 fetchpriority="high"
  • ex-Comm/CX01-footer.html 移除已停用區塊的 Vue 資料檔，減少不必要的腳本
  • css/index.css 移除重複字型匯入，修正第二個字型類別名稱
  • 共用導覽列搜尋圖示統一指向正式搜尋頁 S01-Search-1131012.html

最佳化圖片位置：assets-optimized/images/B03-banner/，首頁已全面改用。

六、VS Code / Live Server / Five Server 與 Git 防膨脹

監看排除設定
  • .vscode/settings.json 已同時設定 files.watcherExclude、liveServer.settings.ignoreFiles 和 fiveServer.ignore
  • 排除：.git/、node_modules/、大型閱讀/旅遊/個人資料夾、pagefind/、reports/、assets-optimized/.cache/
  • Five Server 使用獨立連接埠 5501
  • 修改設定後請執行 Developer: Reload Window
Git 防膨脹
  • .gitignore 已排除封存區、暫存檔、可重新產生的報表
  • 提交前檢查：node tools/check-media-before-git.mjs（檢查 >2 MB 的暫存檔案）
  • assets-optimized/ 中的最終 WebP 仍納入 Git（因是網站部署所需）
  • 既有 9.1 GB 歷史不予改寫，未來另案處理
伺服器使用方式： Live Server → http://127.0.0.1:5500/index.html ｜ Five Server → http://127.0.0.1:5501/index.html

八、日常維護速查表

您要做的事 必要操作
新增或修改文章 HTML 完成後執行 ./tools/rebuild-pagefind.ps1，並檢查 reports/pagefind-build-history.csv
新增首頁／高流量文章大圖 ① 產生最佳化 WebP ② 修改 HTML 使用 assets-optimized/ ③ 確認無引用後封存原圖
發布網站 確認包含 pagefind/、assets-optimized/ 與修改後 HTML；無需上傳封存資料夾
準備 Git 提交 先執行 node tools/check-media-before-git.mjs，檢查是否有大型檔案誤入
Five Server 卡住 停止伺服器、重新載入 VS Code 視窗，再用 5501 開啟
搜尋找不到新文章 重建 Pagefind 索引，並確認文章是完整 HTML 文件（非共用片段）
媒體稽核 執行 npm run media:audit 更新 reports/media-audit.csv
首頁圖片最佳化 執行 npm run media:homepage 產生新的 WebP 副本

九、建議的下一步

  1. 先維持目前首頁與搜尋功能穩定，使用一至兩週觀察載入情況。
  2. 從 reports/media-audit.csv 選擇「檔案大、首頁或常用文章有引用」的下一批圖片處理，分批進行，勿一次全部改寫。
  3. 選擇一個旅遊或閱讀分類的代表文章，示範性加入圖片響應式版本、影片封面與 PDF 縮圖連結，再將做法推廣至同類文章。
  4. 若未來要大幅縮小 Git 歷史，請先另做完整備份與獨立計畫（不混入日常維護）。
