CONTENT ANALYSIS

把四份文件對成一張製作表

分析階段要先回答：有哪些段落、幾張分鏡、每張圖要畫什麼、動畫如何動、哪段旁白對應哪段字幕。

本次分析結果

  • 11 個旁白段落與章節標題
  • 126 張分鏡卡與圖片需求
  • 每張圖片約 5 秒的初始節奏
  • 旁白與字幕使用同一份時間軸
  • 圖片不放字幕，字幕由網頁與影片疊加
核心資料檔app-data.jstimeline.jsoncaptions.jsoncaptions.srt

這些檔案把文字、時間與畫面連在一起，是三個版本共用的資料骨架。

IMAGE & CHARACTER

先固定角色，再替換世界

三個版本共用同一份內容，但用不同視覺主角呈現。角色外觀要穩定，場景、動作、鏡位與光線才可以依分鏡變化。

V2

Q 版墨鏡主角

以主角參考圖為一致性核心，維持臉型、髮型、墨鏡、服裝與比例。

V3

明亮 3D 多啦A夢

保留同一份旁白與分鏡意義，改用明亮 3D 動畫卡通視覺。

V4

明亮 Totoro 閱讀場景

保留內容與節奏，改用溫暖明亮的 Totoro 閱讀場景。

每張圖片提示詞要交代

主角場景動作鏡位光線字幕安全區負面提示詞

VOICE & CAPTIONS

先讓旁白決定時間，再安排圖片

這次使用 YunJhe 男聲旁白。旁白段落、字幕句子與圖片時間軸互相對齊，讓閱讀畫面不會搶在聲音前面或落後太多。

01

取得旁白

使用實際 MP3，確認段落順序與音檔存在。

02

測量時間

依實際語音長度建立段落開始與結束時間。

03

切字幕

依自然句切成每段約兩行的繁體中文字幕。

04

分配圖片

約每 5 秒換一張，並保留語意完整與字幕安全區。

本次完成數據

11 段旁白、總閱讀時間約 607.56 秒；影片加入 3 秒開頭畫面後，成品約 610.57 秒。

DYNAMIC READING WEB

把資料變成可閱讀的網頁

網頁的重點不是塞滿功能，而是讓旁白、字幕、圖片與閱讀節奏自然地一起走。

HTML

封面、舞台、字幕區、控制列、章節導覽與按鈕。

CSS

米白、墨黑、茶色、竹青；慢速淡入、推近、平移與留白。

JavaScript

播放／暫停、上一段、下一段、進度、音量、圖片切換與字幕同步。

手機適配

直立上下排列，橫放壓縮首屏；按鈕保留足夠觸控高度。

重要路徑原則上傳包首頁 → versions/v2/上傳包首頁 → versions/v3-doraemon/上傳包首頁 → versions/v4-totoro/

上傳包不能依賴本機資料夾名稱，所有連結必須使用包內相對路徑。
